## 2. Objective

建立 11 個 domain context 的 package 與 import 邊界骨架：`campaign`、`wallet`、`qr`、`reward`、`notification`、`compliance`、`crm`、`team`、`ip_asset`、`analytics`、`commerce`。每個 domain package 僅為空骨架（`package.json`/`tsconfig.json`/`src/index.ts`，`export {};`），不實作 entity、repository、service、value object 或任何 domain 行為。同時建立三層獨立驗證機制：(a) `dependency-cruiser` 18.1.0 之 resolved-path 邊界規則，其中 `no-cross-domain-import`、`no-deep-import-into-shared`、`no-app-to-app-import` 三條規則由 fixture 正向/負向驗證；`no-domain-self-import` 為 defense-in-depth 規則，其 `aliased-workspace` 判定行為不於本任務以 fixture 負向驗證；(b) 以既有 `typescript` 6.0.3 Compiler API 撰寫之 module specifier 掃描器，為 domain package 以自身 npm 套件名稱 self-import 之決定性主要驗證機制；(c) 對真實 repo 執行之 compliance scan。本任務不將此驗證接入 CI pipeline；`.github/workflows/ci.yml` 不在本任務修改範圍。CI 整合、PR-blocking guardrail、以及更廣泛的 dependency/schema/import scanner 屬 FND-006 範圍。Bare npm workspace 套件名稱 import（例如 `@5min/domain-reward`）之負向 disposable-workspace harness 延後至 FND-006 或另一獨立核准之 architecture-hardening task。

## 10. Implementation Steps

1. Root `package.json`：`workspaces` 新增 `"packages/domain/*"`；`devDependencies` 新增 `"dependency-cruiser": "18.1.0"`；`scripts` 新增 `"test:architecture": "node tests/architecture/run-architecture-tests.mjs"`。
2. 建立 11 個 `packages/domain/<name>/`，每個含 `package.json`（`name: "@5min/domain-<kebab-name>"`、`private: true`、`version: "0.0.1"`、`engines: { "node": ">=24 <25" }`、`main: "src/index.ts"`）、`tsconfig.json`（`extends: "../../../tsconfig.base.json"`，不新增 project references、composite mode 或 path alias）、`src/index.ts`（`export {};`）。
3. 建立 root `.dependency-cruiser.mjs`：四條 `forbidden` 規則（`no-cross-domain-import`、`no-domain-self-import`、`no-deep-import-into-shared`、`no-app-to-app-import`）。內容見技術附錄。
4. 建立 `tests/architecture/run-architecture-tests.mjs`：內含三個獨立階段——(a) 對真實 repo 與 6 個 fixture 執行 `npm exec -- depcruise` resolved-path 檢查（`cwd` 固定為 repo root，target 路徑均為相對 repo root 之完整路徑，不倚賴由 fixture 目錄向上尋找 root package 或 binary）；(b) 以 TypeScript Compiler API 對真實 `packages/domain/*/src/**/*.ts` 與 1 個負向 fixture 執行 module specifier self-import 檢查；(c) 匯總兩階段結果。演算法見技術附錄。
5. 建立技術附錄所列之全部 fixture 檔案（isolated fixture 一律使用相對路徑 import）。
6. 執行 `npm install --package-lock-only --ignore-scripts`（使用已核准之 npm 11.9.0）使 root `package-lock.json` 反映新增之 workspace 成員與依賴，語意範圍見 §11。
7. 確認所有新增/修改檔案落在 §6 Allowed 清單內。

## 11. Acceptance Criteria

**Package skeleton：**

* `packages/domain/` 下恰好存在 11 個目錄，每個恰好含 3 個檔案（合計 33 個檔案）。
* 每個 `packages/domain/<name>/package.json` 之 `name` 為 `@5min/domain-<kebab-name>`（`ip_asset` 目錄 → `@5min/domain-ip-asset`），`engines.node` 為 `">=24 <25"`。

**Workspace / dependency wiring：**

* root `package.json` 之 `workspaces` 包含 `"packages/domain/*"`；`devDependencies["dependency-cruiser"]` 恰為 `"18.1.0"`；`scripts["test:architecture"]` 存在且未併入 `scripts.lint` 或 `scripts.test`。
* root `package-lock.json` 語意驗證（非逐行比對）：既有 root 直接 dependencies 不變；既有 root devDependencies 除新增 `dependency-cruiser: 18.1.0` 外不變；既有各 workspace 成員之直接 dependencies 不變；新增 11 個 domain workspace 項目；新增 `dependency-cruiser@18.1.0` 及其所需 transitive tree；未引入、移除、或變更版本任何無關直接依賴。

**Enforcement mechanism 1 — dependency-cruiser resolved-path boundary tests（僅涵蓋三條規則）：**

* `.dependency-cruiser.mjs` 存在，含 `no-cross-domain-import`、`no-domain-self-import`、`no-deep-import-into-shared`、`no-app-to-app-import` 四條 `severity: "error"` 規則；`no-cross-domain-import` 未設定 `dependencyTypesNot`。
* `no-cross-domain-import`、`no-deep-import-into-shared`、`no-app-to-app-import` 三條規則各自以 fixture 正向/負向驗證：2 個 allowed fixture 各自以 exit code `0` 通過；4 個 forbidden fixture（`no-cross-domain-import` ×2、`no-deep-import-into-shared` ×1、`no-app-to-app-import` ×1）各自以非零 exit code 失敗，且輸出含對應之預期規則 ID，非因設定/剖析/指令執行錯誤而失敗。
* `no-domain-self-import` 不適用上述 fixture 驗證方式；其 `aliased-workspace` 判定行為僅作為 defense-in-depth 存在於設定檔中，不於本任務以 fixture 負向測試證明其實際觸發。

**Enforcement mechanism 2 — TypeScript-API self-import specifier tests（`no-domain-self-import` 之決定性主要驗證）：**

* 以 TypeScript Compiler API 對負向 fixture（`self-import-via-own-name`）執行 module specifier 檢查，正確偵測並回報 `no-domain-self-import`，含檔案與行號診斷。
* 檢查涵蓋 `ImportDeclaration`（含 type-only）、`ExportDeclaration`（含 type-only、含 moduleSpecifier）、`ImportEqualsDeclaration`（external module reference 形式）、動態 `import()`、字串常數形式之 `require()`。

**Enforcement mechanism 3 — real-repository compliance scan：**

* 對真實 repo 執行 dependency-cruiser resolved-path 掃描（`packages/domain packages/shared apps`），exit code 為 `0`。
* 對真實 `packages/domain/*/src/**/*.ts` 執行 TypeScript-API self-import 檢查，回報零違規（現階段骨架每個 `src/index.ts` 僅為 `export {};`，無任何 module specifier）。

**邊界與回歸：**

* 未新增 `packages/infrastructure/**`、`migrations/**`、任何 SQL、任何 domain 行為實作、任何 HTTP route、任何 queue consumer。
* `.github/workflows/ci.yml`、`docs/adr/**`、`CLAUDE.md`、`scripts/dev/**`、`packages/shared/**`、`apps/**` 之 `git diff --name-status` 皆為空。
* 既有 FND-001 驗收項目不回歸。
