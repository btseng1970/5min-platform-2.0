# FND-000｜Dev environment & CI infra

Full 16-field task package，依 Codex Development Spec v1.0 RevB.1 §7（Task Package Standard）展開 §15 digest row。本文件為 repo 內完整版本，Codex 執行以本文件為準；§15 表格僅為會議 digest，不可單獨作為執行依據。

## 1. Task ID
FND-000

## 2. Objective
建立可重現的本地/CI 開發環境：PostgreSQL 16 + pg-boss 測試環境，一條指令啟動；CI 具備空管線骨架（可執行 migration validation 與 integration tests 的位置，本任務不建立實際 migration）；並提供 PostgreSQL 16 宣告式分區能力（partition capability）的冒煙測試，作為 FND-005 event_outbox partition 與 GA-008/39.4 partitioned facts 需求的前置驗證。本任務不建立應用程式碼、不建立 domain schema、不實作業務邏輯。

## 6. Allowed & Forbidden Files
**Allowed（僅限以下路徑）：**
* `.devcontainer/**`
* `docker-compose.yml`
* `.github/workflows/ci.yml`
* `scripts/dev/**`

**Forbidden（本任務不得建立或修改）：**
* `apps/**`、`packages/**`（FND-001/FND-002 範圍）
* `migrations/**`（FND-003/FND-004/FND-005 範圍；本任務僅在 CI/scripts 中執行「一次性、拋棄式」的分區能力驗證 SQL，不得寫入 `migrations/`）
* 任何業務邏輯、domain model、API route
* `docs/adr/**`、`docs/codex-task-packages/**` 以外的 docs 治理文件不在本任務修改範圍

## 7. DB & API Changes
* **無應用程式 schema 變更**。不建立 platform/domain schema（屬 FND-004）。
* pg-boss 啟動時會在其自身管理的 schema（預設 `pgboss`）建立內部工作表；這是 pg-boss 套件自帶行為，非本任務手動 DDL，且不算作 domain schema 違規（GA-004 僅禁止 Redis/memory TokenSource，不禁止 pg-boss 自身 schema）。
* partition capability smoke test 使用**拋棄式（ephemeral）** 測試 schema/table（例如 `_env_check` schema 下的 range-partitioned 表），於測試流程建立並於結束時 DROP，不進入 `migrations/`、不代表任何 domain 資料模型，僅用於驗證 PostgreSQL 16 declarative partitioning + `DETACH PARTITION` 可用。
* 無 API 變更；本任務不涉及 `docs/openapi`。

## 8. Domain Events
無。FND-000 為純基礎設施任務，不發布任何 domain event，不寫入 `platform.event_outbox`（該表本身要到 FND-005 才建立）。

**ADR-000 Stack（本任務唯一允許技術棧）**：TypeScript / Node.js LTS / NestJS / Next.js / PostgreSQL 16 / pg-boss / SQL-first migrations（禁 ORM 自動生成 DDL）/ Kysely 類 query builder。不得引入其他框架、DB client、queue、ORM 或 local-time 邏輯。見 `docs/adr/ADR-000.md`（Accepted）。

**FND-000 直接相關的 GA 條款**：GA-002（環境時區必須設定為可支援 UTC 判斷，容器內不得預設 local timezone 邏輯）、GA-008（partition capability smoke test 直接驗證此條款的技術前提）、GA-013（docker-compose / devcontainer / CI 內僅能安裝 PostgreSQL 16、pg-boss、Node.js LTS 相關工具鏈，不得引入 Redis 或其他未核准 queue/DB client）。其餘 GA 條款於本任務範圍內無直接產出，但仍需在 task prompt 中完整附上（Codex Spec §4 規定：「沿用 v1.0」禁止省略）。

## 10. Implementation Steps
1. `docker-compose.yml`：定義 `postgres`（image: `postgres:16`，含 healthcheck）服務，供本地與 CI 共用；環境變數與 port 透過 `.env.example` 或 compose 預設值管理，不寫入密鑰。
2. `.devcontainer/`：devcontainer.json + Dockerfile（Node.js LTS base），掛載 workspace，postCreate 執行相依安裝腳本；devcontainer 啟動時可連上 compose 定義的 PostgreSQL。
3. `scripts/dev/`：
   * 啟動腳本（一條指令，如 `scripts/dev/up.sh`）：`docker compose up -d` + 等待 healthcheck。
   * 環境 smoke test 腳本：驗證可連線 PostgreSQL 16、版本正確、可連線 pg-boss（啟動 pg-boss instance 並確認其 schema 建立成功）。
   * partition capability smoke test 腳本：在 ephemeral schema 建立 range-partitioned 表（模擬 GA-008/39.4 需求：PK 含分區鍵）、插入跨分區資料、執行 `DETACH PARTITION`、驗證結果後清除 ephemeral schema。
4. `.github/workflows/ci.yml`：空管線骨架 —— checkout、啟動 PostgreSQL 16 service container、安裝 Node.js LTS、執行上述 smoke test 腳本作為 CI job；預留 migration validation 與 integration test 的 job step（本任務不需要真正的 migration 可執行，因為 migrations/ 尚未建立，但 CI 結構需能在後續任務接入時無需重構）。
5. 確認所有新增檔案落在 Allowed 清單內；不得觸碰 `apps/`、`packages/`、`migrations/`。

## 11. Acceptance Criteria
* `docker-compose up`（或等效一條指令）可啟動 PostgreSQL 16 環境並通過 healthcheck。
* pg-boss 測試環境可啟動並成功初始化其內部 schema（證明 queue infra 可用，不代表任何 domain 使用）。
* CI（`.github/workflows/ci.yml`）可在乾淨環境執行本任務的 smoke test 與 partition capability test 並全部通過；管線結構預留 migration validation / integration test 位置供後續任務接入。
* Partition capability smoke test 證明：PostgreSQL 16 declarative range partitioning 可用、分區鍵可正確納入 PK/unique index、`DETACH PARTITION` 可執行且不遺失資料 —— 對應 GA-008 與 TDS §39.4/39.5 之技術前提。
* 未新增任何 `apps/`、`packages/`、`migrations/` 內容；未安裝任何 ADR-000 allowlist 之外的依賴（GA-013）。
* Repo 內無 secrets（.env 等敏感檔不得 commit）。

## 12. Tests Required
* **Environment smoke test**：PostgreSQL 16 連線與版本驗證、pg-boss 啟動驗證。
* **Partition capability test**：建立分區表（含分區鍵於 PK/unique）、跨分區寫入、`DETACH PARTITION`、驗證資料完整性與清理成功。
* **CI negative check**（基本骨架階段，非完整 FND-006 scanner）：CI 若 PostgreSQL 16 未就緒或 pg-boss 初始化失敗，pipeline 必須 fail，不得靜默通過。

## 13. Seed Data
無。FND-000 不涉及 domain 資料，無需 §14 定義之 seed pack（market/member/wallet/qr/reward/team/notification/legacy seed 均從 FND-004 之後才適用）。Partition capability test 使用測試流程內產生、測試結束即銷毀的 ephemeral 資料，不屬於任何正式 seed pack。

## 14. Observability
* PostgreSQL 容器須設定 Docker healthcheck（如 `pg_isready`），`docker-compose up` 後可用 `docker compose ps` 觀察健康狀態。
* CI job 需輸出清楚的 smoke test / partition test 結果 log（pass/fail 明確），供後續除錯；本任務不需實作 FND-010 的 correlation_id 追蹤（該項為獨立任務），但 CI log 格式應避免混淆，為 FND-010 預留擴充空間。

## 15. Rollback
* 環境定義為聲明式（docker-compose / devcontainer / CI workflow / scripts），無資料庫遷移或應用程式狀態需要回滾。
* Revert 方式：`git revert` 本任務 commit 即可完全移除新增檔案；`docker compose down -v` 清除本地 volume 即可回到乾淨狀態。
* 無 forward-fix 必要性（本任務不產生任何生產環境影響）。
